# History — 세션 기록 저장

세션 종료 시 실행한다. 이번 세션의 작업 내용을 수집하여 `memory/` 디렉토리에 기록 파일을 생성한다.

## 1단계: 세션 번호 결정

`memory/` 디렉토리의 기존 파일을 확인한다.
기존 파일 중 가장 높은 세션 번호 + 1 을 새 세션 번호로 사용한다.

파일명 형식: `memory/session-{Claude 이름}-{N}-{주제 키워드}.md`
- 주제 키워드는 이번 세션의 핵심 작업을 2~3단어로 요약한다.
- 예: `session-styler-1-style-cleanup.md`, `session-developer-2-service-extraction.md`

## 2단계: 작업 내용 수집

다음 정보를 수집한다:

### 커밋 목록
`git log --oneline` 에서 이번 세션에서 생성한 커밋을 식별한다.
이전 세션 기록의 마지막 커밋 이후 커밋들이 이번 세션 것이다.

### 변경 파일 요약
`git diff` 또는 커밋 히스토리에서 이번 세션에 변경된 파일 목록을 수집한다.

### 대화 내용 분석
이번 세션의 대화에서 다음을 추출한다:
- 내린 설계/방향 결정
- 작업 중 발견했으나 해결하지 않은 문제
- 다음 세션에서 이어할 작업

## 3단계: 세션 파일 작성

다음 구조로 작성한다:

```markdown
# Session {N}: {주제}

**날짜**: YYYY-MM-DD

## 이번 세션에서 한 일
- 구체적 작업 내용 (커밋 단위로 정리)

## 커밋 목록
- `{hash}` {message}

## 변경된 파일
- 파일 목록 (신규/수정/삭제 구분)

## 결정 사항
- 이번 세션에서 내린 설계/방향 결정과 그 이유

## 발견한 문제
- 작업 중 발견했으나 이번에 해결하지 않은 것
- Phase 2에서 다룰 사항 등

## 다음 세션 할 일
- 이어서 해야 할 구체적 작업
```

## 4단계: cross-session 상태 업데이트

### MEMORY.md (auto-memory) 업데이트
`~/.claude/projects/` 아래의 auto-memory 파일에 새 세션 항목을 추가한다:
- 세션 테이블에 새 행 추가
- 결정 사항 중 cross-session으로 기억해야 할 것이 있으면 반영

### CLAUDE.md 업데이트 확인
이번 세션에서 프로젝트 규칙이나 컨벤션에 변경이 있었다면 CLAUDE.md 업데이트를 제안한다.
(자동으로 수정하지 않고, 변경이 필요한 부분과 이유를 보고한다.)
