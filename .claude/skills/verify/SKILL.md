# Verify — 변경 사항 검증

코드 변경 후 커밋 전에 실행한다. 아래 6단계를 순서대로 수행하고 결과를 보고한다.

## 1단계: 테스트 통과 확인

`./gradlew test` 를 실행한다.

- **통과**: 다음 단계로 진행한다.
- **실패**: 실패한 테스트와 원인을 보고하고 **여기서 멈춘다**. 코드 수정을 임의로 제안하지 않는다.

## 2단계: diff 점검

`git diff` (unstaged)와 `git diff --staged` (staged)를 모두 확인한다.

점검 항목:
- 의도하지 않은 파일이 변경되지 않았는가
- 의도하지 않은 줄이 바뀌지 않았는가 (공백, import 정리, 주석 등 포함)
- 변경된 파일 목록과 각 파일의 변경 요약을 보고한다

## 3단계: 구조/작동 분리 확인

변경된 코드가 다음 중 어디에 해당하는지 판단한다:

**구조 변경** (Phase 1 허용):
- 이름 바꾸기, 메서드/클래스 추출, 패키지 이동
- 의존성 정리, 계층 분리, 스타일 통일

**작동 변경** (Phase 1 금지):
- 로직 변경, 새 기능 추가, 예외 처리 방식 변경
- 트랜잭션 경계 변경, 정책 변경

구조 변경과 작동 변경이 섞여 있으면 분리 방안을 제안한다.

## 4단계: 30초 규칙

현재 diff 전체를 한 문장으로 설명할 수 있는지 판단한다.

- **설명 가능**: 그 한 문장을 보고한다.
- **설명 불가**: 커밋을 쪼개는 구체적 방안을 제안한다.

## 5단계: 코드 컨벤션 확인

변경된 파일에 한해, CLAUDE.md의 코드 컨벤션 섹션 기준으로 위반 여부를 점검한다.
새로 도입된 위반만 보고한다 (기존 코드의 위반은 이 단계에서 보고하지 않는다).

## 6단계: 결과 보고

위 5단계 결과를 다음 형식으로 요약한다:

```
## Verify 결과

| 항목 | 결과 |
|------|------|
| 테스트 | PASS / FAIL |
| 의도하지 않은 변경 | 없음 / 있음 (상세) |
| 구조/작동 분리 | 구조만 / 작동만 / 혼합 (상세) |
| 30초 규칙 | 통과 (한 문장 요약) / 미통과 (분리 방안) |
| 컨벤션 | 위반 없음 / 위반 있음 (상세) |

커밋 준비: OK / NG
```

모든 항목이 통과이면 AngularJS Convention에 맞는 커밋 메시지를 제안한다.
