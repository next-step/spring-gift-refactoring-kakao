# Decision — 결정 기록

작업 중 두 가지 이상의 선택지가 있을 때 실행한다.
결정을 내리는 과정과 결과를 구조화하여 기록한다.

## 1단계: 결정 상황 정리

현재 어떤 문제에 직면했는지 정리한다.

- **맥락**: 어떤 작업을 하다가 이 결정이 필요해졌는가
- **질문**: 한 문장으로 표현한 핵심 질문 (예: "Custom Validator를 Phase 1에서 Spring Validation으로 전환할 것인가?")

## 2단계: 선택지 제시

각 선택지를 다음 관점으로 정리하여 사용자에게 제시한다:

- **선택지 설명**: 무엇을 하는가
- **장점**: 이 선택의 이점
- **단점**: 이 선택의 비용이나 위험
- **영향 범위**: 어떤 파일/모듈이 영향받는가
- **미션 규율과의 관계**: 구조/작동 분리 원칙에 부합하는가

AskUserQuestion 도구를 사용하여 선택지를 제시한다.

## 3단계: 토의

사용자의 의견을 듣고, 필요하면 추가 정보를 조사한다.
사용자가 다른 선택지를 제안하면 동일한 관점으로 분석한다.

## 4단계: 결정 기록

결정이 내려지면 `memory/decisions.md` 파일에 기록한다.
파일이 없으면 새로 생성한다. 있으면 끝에 추가한다.

기록 형식:

```markdown
## D{번호}: {핵심 질문 한 문장}

**날짜**: YYYY-MM-DD
**세션**: session-{N}
**상태**: 확정 / 보류

### 맥락
왜 이 결정이 필요했는가. 어떤 작업 중에 발생했는가.

### 선택지
1. **{선택지 A}**: 설명. 장점/단점.
2. **{선택지 B}**: 설명. 장점/단점.

### 결정
선택한 항목과 그 이유.

### 영향
이 결정으로 인해 시스템이나 작업 계획이 어떻게 달라지는가.
- 변경되는 파일/모듈
- 후속 작업에 미치는 영향
- 주의해야 할 사항
```

## 5단계: 관련 파일 업데이트

결정에 따라 다음 파일의 업데이트가 필요한지 확인하고 제안한다:

- **CLAUDE.md**: 프로젝트 규칙이나 컨벤션이 변경된 경우
- **README.md**: 기능 목록이나 구현 전략이 변경된 경우
- **현재 세션 memory 파일**: 결정 사항 섹션에 참조 추가 (예: "D3 참조")

업데이트는 제안만 하고, 사용자 승인 후 반영한다.
