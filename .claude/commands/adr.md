Role: ADR(Architecture Decision Record) 작성기

## 입력

$ARGUMENTS

사용자가 자유 형식으로 제공하는 정보:
- 제목, 선택지(장단점 포함), 결정 사항, 관련 코드/커밋

## 실행 절차

### 1단계: 다음 ADR 번호 결정

`docs/adr/` 디렉토리에서 기존 ADR 파일을 탐색한다.
- 파일명 패턴: `NNN-*.md` (예: `001-price-calculation-location.md`)
- 가장 큰 번호 + 1을 다음 번호로 사용한다.
- 파일이 없으면 001부터 시작한다.

### 2단계: 사용자 입력 파싱

$ARGUMENTS에서 다음을 추출한다:
- **제목**: 결정 주제
- **선택지**: 검토한 옵션과 각각의 장단점
- **결정**: 선택한 옵션과 이유
- **관련 코드/커밋**: 파일 경로나 커밋 해시 (선택)

불명확한 부분이 있으면 사용자에게 질문한다. 추측하지 않는다.

### 3단계: 관련 코드 읽기 (선택)

관련 코드 파일이 명시되어 있으면 해당 파일을 읽어 맥락을 보충한다.
코드 레벨 선택지인 경우, 실제 코드를 확인하여 정확한 내용을 작성한다.

### 4단계: ADR 파일 생성

아래 포맷으로 `docs/adr/NNN-slug.md` 파일을 생성한다.
- slug는 제목을 영문 kebab-case로 변환한 것이다.
- 날짜는 오늘 날짜를 사용한다.

```markdown
# NNN. 제목

- **상태**: Accepted
- **날짜**: YYYY-MM-DD
- **관련 커밋**: (있으면 기재, 없으면 이 줄 생략)

## 맥락 (Context)

왜 이 결정이 필요했는지 배경 설명

## 선택지 (Options)

### A. 옵션명

- 장점: ...
- 단점: ...

### B. 옵션명

- 장점: ...
- 단점: ...

## 결정 (Decision)

선택한 옵션과 핵심 이유

## 결과 (Consequences)

이 결정으로 인한 영향과 트레이드오프
```

### 5단계: 결과 보고

생성한 파일 경로와 내용 요약을 보고한다.

## 제약사항

- 기존 프로덕션 코드를 절대 수정하지 않는다.
- ADR은 사실 기반으로만 작성한다. 추측이나 가정을 넣지 않는다.
- 불확실한 부분은 `<!-- TODO: 확인 필요 -->` 주석으로 남긴다.
- `docs/adr/` 디렉토리가 없으면 생성한다.
