# ADR 001: 인증 방식으로 JWT 선택

> 작성일: 2026-03-05
> 상태: Accepted

## Context (맥락)

사용자 인증 및 API 보호를 위한 인증 방식을 결정해야 했다. 선택지로는 세션 기반 인증, JWT 토큰 기반 인증, OAuth2 표준 구현 등이 있었다. 프로젝트는 REST API 기반이며, 카카오 소셜 로그인과의 통합이 필요했다.

## Decision (결정)

JWT(JSON Web Token) 기반 인증을 채택한다. jjwt 라이브러리(0.13.0)를 사용하며, 사용자 이메일을 subject로 저장한다. HMAC-SHA 알고리즘으로 서명하고, 설정 파일에서 secret과 만료 시간을 관리한다.

## Consequences (결과)

### Pros
- 서버 측 세션 저장소가 불필요하여 수평 확장에 유리하다
- REST API의 무상태(stateless) 원칙에 부합한다
- 카카오 로그인 후 자체 JWT 발급으로 인증 흐름이 단순해진다

### Cons
- 토큰 만료 전 강제 무효화가 어렵다 (블랙리스트 미구현)
- 토큰 탈취 시 만료까지 악용 가능성이 존재한다
