# ADR-0002: 주문 금액 저장 정책

## 상태
채택됨

## 맥락
주문 생성 시 총 금액(totalPrice)을 별도로 저장하지 않고, 필요할 때마다 상품 가격 × 수량으로 계산하고 있었다.
상품 가격이 변경되면 과거 주문의 금액도 변경되는 문제가 있다.

## 선택지

### Option A: 주문 시 금액 저장 (채택)
주문 생성 시점의 총 금액을 orders 테이블에 저장한다.

- 장점: 주문 시점의 가격이 보존되어 상품 가격 변경에 영향받지 않는다
- 장점: 금액 조회 시 JOIN 없이 단일 테이블에서 조회 가능하다
- 단점: 저장 공간이 추가로 필요하다 (INT 4바이트)

### Option B: 매번 계산
기존 방식대로 상품 가격 × 수량으로 필요할 때 계산한다.

- 장점: 스키마 변경이 없다
- 단점: 상품 가격 변경 시 과거 주문 금액이 달라진다
- 단점: 금액 계산 로직이 여러 곳에 중복된다

## 결정
Option A를 채택한다.

"선물하기" 서비스에서 주문 금액은 결제 기록이므로, 주문 시점의 가격을 불변으로 보존해야 한다.
기존 데이터는 현재 상품 가격 기준으로 backfill한다 (V3 마이그레이션).

## 결과
- orders 테이블에 total_price 컬럼 추가 (V3 마이그레이션)
- Order 엔티티에서 totalPrice를 저장하고, 가격 계산을 한 곳으로 집중한다
