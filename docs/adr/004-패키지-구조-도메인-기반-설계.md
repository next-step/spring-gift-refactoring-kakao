# ADR 004: 패키지 구조 - 도메인 기반 설계

> 작성일: 2026-03-05
> 상태: Accepted

## Context (맥락)

프로젝트의 패키지 구조를 결정해야 했다. 계층형 구조(controller, service, repository 패키지)와 도메인형 구조(도메인별 패키지) 중 선택이 필요했다.

## Decision (결정)

도메인 기반 패키지 구조를 채택한다. 각 도메인(product, category, option, order, wish, member, auth)별로 패키지를 구성하고, 해당 도메인의 Controller, Service, Repository, Entity, DTO를 같은 패키지에 배치한다. 공통 설정은 config 패키지에 위치시킨다.

## Consequences (결과)

### Pros
- 도메인별 응집도가 높아져 관련 코드를 한 곳에서 파악할 수 있다
- 도메인 단위로 모듈화하기 용이하여 향후 마이크로서비스 분리에 유리하다
- 새 도메인 추가 시 기존 패키지에 영향을 주지 않는다

### Cons
- 도메인 간 공통 로직의 위치를 별도로 결정해야 한다
- 계층형 구조에 익숙한 개발자에게 낯설 수 있다
