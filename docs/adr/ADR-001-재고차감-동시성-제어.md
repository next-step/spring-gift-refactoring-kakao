# ADR-001: 재고 차감 동시성 제어 — 비관적 락 vs 낙관적 락

## 상태
승인됨

## 맥락
`OrderService.createOrder()`에서 `option.subtractQuantity(quantity)`를 호출할 때 락 없이 조회하고 있다.
두 요청이 동시에 같은 옵션을 조회하면 둘 다 재고 검증을 통과하여 초과 차감(oversell)이 발생할 수 있다.

## 선택지

### A. 낙관적 락 (`@Version`)
- Option 엔티티에 `@Version` 필드 추가
- 충돌 시 `OptimisticLockException` 발생 → 호출부에서 재시도 로직 필요
- 장점: 락 대기 없이 높은 처리량
- 단점: 재고가 0에 가까워지면 충돌률 급증 → 재시도 비용 증가, 사용자 경험 저하

### B. 비관적 락 (`@Lock(PESSIMISTIC_WRITE)`)
- `SELECT ... FOR UPDATE`로 행 단위 락 획득
- 장점: 충돌 시 대기 후 순차 처리, 재시도 불필요, 정합성 보장
- 단점: 동시 요청이 많을 경우 대기 시간 발생, 데드락 가능성

## 결정
**B. 비관적 락**을 선택한다.

## 근거
- 재고가 소진될수록 같은 옵션에 대한 동시 주문 충돌률이 급증한다.
- 낙관적 락은 충돌 시 사용자에게 "재시도"를 요구하지만, 비관적 락은 "대기 후 처리"로 더 나은 UX를 제공한다.
- 현재 서비스 규모에서 행 단위 락의 대기 비용은 무시할 수 있는 수준이다.

## 검증 방법
- 동시성 테스트: N개 스레드가 동시에 같은 옵션에 주문 → 재고만큼만 성공, 나머지 실패, 최종 재고 0 확인
