# ADR-0001: 카카오 메시지 발송 실패 시 주문 롤백 정책

## 상태
대체됨 (ADR-0003으로 대체)

## 맥락
주문 처리 시 재고 차감, 포인트 차감, 주문 저장, 카카오 메시지 발송이 하나의 트랜잭션 안에서 수행된다.
카카오 메시지 발송이 실패했을 때 주문을 어떻게 처리할지 결정해야 한다.

## 선택지

### Option A: 메시지 실패 시 전체 롤백 (채택)
try-catch를 제거하여 예외가 @Transactional 경계까지 전파되도록 한다.
재고, 포인트, 주문이 모두 롤백된다.

- 장점: 구현이 단순하고 데이터 정합성이 보장된다
- 단점: 메시지 발송 실패만으로 주문 자체가 실패한다

### Option B: 메시지 실패 무시 (변경 전)
try-catch로 예외를 삼켜서 주문은 성공하되 알림만 누락된다.

- 장점: 주문 성공률이 높다
- 단점: 사용자가 알림을 받지 못해도 알 수 없다

### Option C: 비동기 재시도 큐
메시지 발송을 비동기로 분리하고 실패 시 재시도한다.

- 장점: 주문과 알림을 독립적으로 처리할 수 있다
- 단점: 메시지 큐, 재시도 로직, 실패 테이블 등 현재 프로젝트 규모에 과도한 인프라가 필요하다

## 결정
Option A를 채택한다.

"선물하기" 서비스 특성상 메시지가 전달되지 않는 것보다 주문을 막는 것이 더 안전하다.
현재 프로젝트 규모에서 가장 단순하면서도 데이터 정합성을 보장하는 방법이다.

## 결과
- `OrderService.sendKakaoMessageIfPossible()`에서 try-catch를 제거했다
- 카카오 메시지 발송 실패 시 재고와 포인트가 롤백되는 것을 Cucumber 테스트로 검증한다
