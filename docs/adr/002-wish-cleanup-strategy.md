# ADR-002: 주문 시 위시 삭제 전략

## 상태

채택됨

## 맥락

주문이 완료되면 해당 상품이 위시리스트에 남아있을 이유가 없다.
위시 삭제를 구현하는 방식은 크게 두 가지이다:

1. **트랜잭션 내 동기 삭제** — `OrderService.createOrder()` 안에서 직접 삭제
2. **이벤트 기반 비동기 삭제** — 주문 완료 이벤트 발행 후 리스너에서 삭제

## 결정

트랜잭션 내 동기 삭제를 선택한다.

## 근거

- 주문과 위시 삭제는 하나의 논리 작업이다.
  주문은 성공했는데 위시 삭제가 실패하면 사용자에게 불일치한 상태가 보인다.
- 동기 삭제는 같은 `@Transactional` 안에 있으므로,
  주문이 롤백되면 위시 삭제도 함께 롤백된다.
- 위시가 없는 상품을 주문하는 경우 `ifPresent`로 무시하므로 부작용이 없다.

## 대안: 이벤트 기반 비동기 삭제

- 장점: OrderService가 WishRepository에 의존하지 않아 결합도가 낮아진다.
- 단점: 이벤트 리스너 실패 시 위시가 남아있게 된다.
  카카오 메시지 전송과 달리, 위시 삭제는 실패하면 사용자에게 직접 보이는 불일치이므로
  "실패해도 괜찮다"는 전제가 성립하지 않는다.

## 증거

E2E 테스트 시나리오 "주문하면 해당 상품의 위시가 삭제된다"에서
위시를 재조회하여 삭제 상태를 확인한다.
