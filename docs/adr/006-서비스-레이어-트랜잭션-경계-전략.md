# ADR 006: 서비스 레이어 트랜잭션 경계 전략

> 작성일: 2026-03-05
> 상태: Accepted

## Context (맥락)

Service Layer 전체를 점검한 결과 두 가지 문제를 발견했다.

1. **KakaoAuthService**: `jakarta.transaction.Transactional`을 private 메서드에 적용하여 Spring AOP 프록시가 동작하지 않아 트랜잭션이 미적용되는 치명적 버그가 있었다.
2. **OrderService**: 외부 카카오 메시지 API 호출이 `@Transactional` 내부에서 실행되어, API 지연/장애 시 DB 커넥션이 불필요하게 점유되는 구조적 문제가 있었다.

## Decision (결정)

### 트랜잭션 컨벤션

- 모든 서비스는 `org.springframework.transaction.annotation.Transactional`을 사용한다.
- 클래스 레벨에 `@Transactional(readOnly = true)`를 기본 적용한다.
- 쓰기 메서드에만 `@Transactional`을 오버라이드한다.
- private 메서드에 `@Transactional`을 사용하지 않는다 (Spring AOP 프록시 미적용).

### KakaoAuthService 수정

- DB 쓰기 로직(`findOrCreate` + 카카오 토큰 업데이트)을 `MemberService.findOrCreateByEmailAndUpdateKakaoToken()`으로 위임하여 self-invocation 문제를 해결한다.
- KakaoAuthService 자체는 `readOnly = true`로 설정하고, 외부 API 호출 후 MemberService에 위임한다.

### OrderService 외부 API 분리

- `ApplicationEventPublisher`를 통해 `OrderPlacedEvent`를 발행한다.
- `OrderEventListener`에서 `@TransactionalEventListener(phase = AFTER_COMMIT)`으로 트랜잭션 커밋 후 카카오 메시지를 발송한다.
- 이로써 외부 API 호출이 트랜잭션 밖에서 실행되어 DB 커넥션 점유 문제를 해결한다.

## Consequences (결과)

### 긍정적

- KakaoAuthService의 DB 쓰기가 실제 트랜잭션 내에서 수행되어 데이터 정합성이 보장된다.
- OrderService의 외부 API 호출이 트랜잭션 밖에서 실행되어 DB 커넥션 풀 고갈 위험이 제거된다.
- 전 서비스가 동일한 `readOnly` 패턴을 따라 일관성이 확보된다.
- 이벤트 기반 구조로 주문과 알림의 관심사가 분리된다.

### 부정적

- MemberService에 카카오 인증 관련 메서드가 추가되어 책임이 약간 늘어난다.
- 이벤트 기반 구조로 인해 카카오 메시지 발송 실패를 동기적으로 확인할 수 없다 (기존에도 실패를 무시했으므로 실질적 영향 없음).
