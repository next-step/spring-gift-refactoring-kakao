# ADR 007: 통합 테스트 인프라 전략

> 작성일: 2026-03-05
> 상태: Accepted

## Context (맥락)

ADR 006에서 서비스 레이어 트랜잭션 경계를 재정립했으나, 현재 모든 테스트가 Mockito 기반 단위 테스트(22개)여서 **트랜잭션 롤백, 이벤트 리스너 동작 등 실제 Spring 컨텍스트에서만 검증 가능한 동작**을 확인할 수 없다.

기존 `application-test.properties`는 H2(`MODE=MYSQL`, `ddl-auto=create-drop`, `flyway.enabled=false`)를 사용하고 있었으나, 운영 환경은 MySQL + Flyway 마이그레이션이므로 다음 한계가 있었다:

- H2와 MySQL의 SQL 방언 차이를 잡지 못함
- Flyway 마이그레이션 스크립트 자체가 테스트되지 않음
- `ddl-auto=create-drop`으로 생성된 스키마와 실제 마이그레이션 스키마가 다를 수 있음

또한 통합 테스트에서 `@Transactional`을 사용하면, 서비스의 트랜잭션이 테스트 트랜잭션에 참여(PROPAGATION_REQUIRED)하여 **서비스 자체의 커밋/롤백을 검증할 수 없는 문제**가 있었다.

## Decision (결정)

### Testcontainers MySQL 도입

- `jdbc:tc:mysql:8.0:///testdb` JDBC URL로 MySQL 컨테이너를 자동 시작한다.
- `flyway.enabled=true`로 실제 Flyway 마이그레이션 스크립트로 스키마를 생성한다.
- `ddl-auto=validate`로 JPA 엔티티와 마이그레이션 스키마 불일치를 즉시 감지한다.

### 통합 테스트 어노테이션 이원화

| 어노테이션 | `@Transactional` | 용도 |
|-----------|:-:|------|
| `@IntegrationTest` | O | 단순 DB 읽기/쓰기 검증. 테스트 후 자동 롤백으로 격리 |
| `@IntegrationTestWithoutTx` | X | 트랜잭션 롤백 검증, `@TransactionalEventListener(AFTER_COMMIT)` 검증 |

`@IntegrationTestWithoutTx`는 서비스가 자체 트랜잭션을 관리하도록 테스트 레벨 트랜잭션 없이 실행한다. 테스트 데이터 정리는 `@AfterEach`에서 FK 역순으로 삭제한다.

### 통합 테스트 픽스처

`IntegrationTestFixtures`는 Repository를 받아 실제 DB에 저장하는 헬퍼를 제공한다. 기존 `TestFixtures`는 리플렉션으로 ID를 설정하는 비영속 객체용이므로 역할을 분리한다.

### 외부 의존성 처리

통합 테스트에서 카카오 API 등 외부 의존성은 `@MockBean`으로 대체한다.

## Consequences (결과)

### Pros
- 실제 MySQL에서 Flyway 마이그레이션과 JPA 엔티티 매핑을 함께 검증할 수 있다
- 트랜잭션 롤백, 이벤트 리스너 등 Spring 컨텍스트 의존 동작을 실제로 검증할 수 있다
- 어노테이션 이원화로 테스트 의도가 명확하게 드러난다
- H2/MySQL 방언 차이로 인한 운영 환경 장애 위험이 제거된다

### Cons
- 테스트 실행 시 Docker Desktop이 실행 중이어야 한다
- 컨테이너 시작으로 인해 첫 통합 테스트 실행 시간이 증가한다
- `@IntegrationTestWithoutTx` 사용 시 테스트 데이터를 수동으로 정리해야 한다
