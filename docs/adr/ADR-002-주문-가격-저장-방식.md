# ADR-002: 주문 가격 저장 방식 — 스냅샷 저장 vs 매번 계산

## 상태
승인됨

## 맥락
현재 `OrderService.calculatePrice()`에서 `option.getProduct().getPrice() * quantity`를 계산하지만,
이 값을 `Order` 엔티티에 저장하지 않는다. 주문 이력 조회 시 상품의 현재 가격으로 계산되어
상품 가격 변경 시 과거 주문 이력의 금액이 달라지는 문제가 있다.

## 선택지

### A. 매번 계산 (현행)
- Order에 가격 필드 없음. 조회 시 `option.getProduct().getPrice() * quantity`로 계산
- 장점: 스키마 단순
- 단점: 상품 가격 변경 시 과거 주문 금액이 소급 변경됨. 정산, 환불 등에서 치명적

### B. totalPrice 스냅샷 저장
- Order 엔티티에 `totalPrice` 필드 추가, 주문 생성 시점에 확정
- 장점: 주문 시점 가격이 영구 보존됨. 정산/환불 안전
- 단점: 스키마 변경 필요 (마이그레이션)

## 결정
**B. totalPrice 스냅샷 저장**을 선택한다.

## 근거
- 주문 시점의 가격은 확정된 값이어야 한다. 상품 가격이 변경되더라도 과거 주문의 가격은 유지되어야 한다.
- 가격 계산 로직을 `Order` 생성자로 이동하면 도메인 응집도도 함께 향상된다.
- Flyway V3 마이그레이션으로 스키마 변경을 관리한다.

## 검증 방법
- 주문 생성 후 `OrderResponse`에 `totalPrice`가 포함되는지 확인
- 상품 가격 변경 후 기존 주문의 `totalPrice`가 변하지 않는지 확인
