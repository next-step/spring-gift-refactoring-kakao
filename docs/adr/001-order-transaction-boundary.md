# ADR-001: OrderService.createOrder 트랜잭션 경계

## 상태

채택됨

## 맥락

`OrderService.createOrder()`는 다음 세 가지 상태 변경을 수행한다:

1. 옵션 재고 차감 (`option.subtractQuantity`)
2. 회원 포인트 차감 (`member.deductPoint`)
3. 주문 저장 (`orderRepository.save`)

이 중 하나라도 실패하면(예: 포인트 부족) 나머지도 취소되어야 한다.
그렇지 않으면 포인트는 차감되지 않았는데 재고만 줄어드는 불일치가 발생한다.

## 결정

`OrderService.createOrder()`에 `@Transactional`을 설정하여
세 작업을 하나의 트랜잭션으로 묶는다.

## 근거

- 재고 차감, 포인트 차감, 주문 저장은 하나의 논리 작업이다.
  부분 성공은 데이터 불일치를 의미한다.
- 포인트 차감이 실패하면 재고 차감도 롤백되어야 한다.
- `@Transactional`은 이 원자성을 선언적으로 보장한다.

## 증거

E2E 테스트 시나리오 "포인트가 부족하면 주문에 실패하고 재고가 원복된다"에서
포인트 부족으로 주문이 실패한 뒤 재고를 재조회하여 원래 값(10개)이 유지됨을 확인한다.

## 대안

- 각 작업에 개별 트랜잭션 + 보상 트랜잭션(Saga 패턴): 분산 시스템이 아닌 단일 DB이므로 불필요한 복잡성.
- 트랜잭션 없이 수동 롤백: 실패 경로마다 롤백 코드를 작성해야 하며 누락 위험이 크다.
