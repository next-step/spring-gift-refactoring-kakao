# 2단계 - 리팩터링 완성하기

## 목표

작동 변경을 안전하게 수행하고, 그 결과를 증거로 보여준다.

## 원칙

- **작동 변경은 반드시 증거와 함께**: 상태를 재조회하거나 결과를 관찰 가능한 방식으로 검증한다.
- **구조 변경과 작동 변경을 섞지 않는다**: 커밋을 분리한다.
- **변경 전에 한 줄씩 적고 시작한다**: 무엇을 바꾸는지, 무엇을 바꾸지 않는지, 무엇이 이를 증명하는지.
- **ADR은 트레이드오프가 있을 때 남긴다**.

## 작업 흐름

1. README 체크리스트에 다음 작업이 적혀 있어야 코드 수정을 시작한다.
2. 작업 단위마다 테스트를 먼저 작성하거나 수정한 뒤, 구현한다.
3. git diff를 자주 확인해 의도하지 않은 변경을 통제한다.
4. 커밋은 목적 1개, 설명 가능한 diff로만 한다.
