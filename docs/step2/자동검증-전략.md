# 자동 검증 도구 도입 전략

## 현재 상태

- `build.gradle.kts`에 **ktlint** 설정 있으나, 소스 코드가 Java이므로 실질적 효과 없음
- 계층 규칙(Controller→Service→Repository)을 문서로만 관리 중 — 위반 시 사람이 잡아야 함
- 실제 위반 사례 존재:
  - `AdminProductController` → `CategoryRepository` 직접 import
  - `OrderService` → 3개 타 도메인 Repository import (Member, Option, Wish)

---

## 도입 도구

### 1. Spotless — Java 코드 포매팅

**왜 필요한가**: ktlint은 Kotlin 전용. Java 소스에 대한 자동 포매팅이 없는 상태.

**설정 범위**:
- google-java-format 적용 (들여쓰기, import 정렬, 공백 등)
- `./gradlew spotlessCheck`로 CI에서 검증
- `./gradlew spotlessApply`로 자동 수정

**도입 순서**:
1. Spotless 플러그인 + google-java-format 설정 추가
2. `spotlessApply` 실행하여 기존 코드 일괄 포매팅
3. 전체 테스트 통과 확인
4. 포매팅 결과를 단독 커밋 (구조/작동 변경 없음)

### 2. ArchUnit — 계층 구조 자동 검증

**왜 필요한가**: "Controller가 Repository를 직접 사용하면 안 된다" 같은 규칙을 코드로 강제.

**적용할 규칙** (우선순위순):

| # | 규칙 | 검증 내용 | 현재 위반 여부 |
|---|------|----------|--------------|
| 1 | Controller → Repository 금지 | `@Controller`/`@RestController` 클래스는 `Repository`를 필드로 가질 수 없음 | **위반**: AdminProductController → CategoryRepository |
| 2 | 순환 의존 금지 | 패키지 간 순환 참조 없음 | 위반 없음 |
| 3 | 네이밍 규칙 | Controller/Service/Repository 접미사 일치 | 위반 없음 |

**도입 순서**:
1. ArchUnit 의존성 추가
2. 규칙 2, 3 먼저 추가 (현재 위반 없는 것부터 — 즉시 통과)
3. AdminProductController의 CategoryRepository 의존 제거 (ProductService 또는 CategoryService 경유로 변경)
4. 규칙 1 추가 (모든 Controller가 통과하는 상태에서)

## 작업 순서

### Step 1: Spotless 도입 + 일괄 포매팅

```
1-1. build.gradle.kts에 Spotless 플러그인 추가
1-2. spotlessApply 실행
1-3. 전체 테스트 통과 확인
1-4. 커밋: "chore: Spotless + google-java-format 도입 및 일괄 포매팅"
```

### Step 2: ArchUnit 도입 + 안전한 규칙부터

```
2-1. build.gradle.kts에 ArchUnit 의존성 추가
2-2. ArchitectureTest 클래스 생성 — 순환 의존 금지 + 네이밍 규칙
2-3. 테스트 통과 확인
2-4. 커밋: "test: ArchUnit 도입 — 순환 의존 금지, 네이밍 규칙 검증"
```

### Step 3: 위반 수정 + Controller→Repository 금지 규칙

```
3-1. AdminProductController에서 CategoryRepository 의존 제거
     → CategoryService에 findAllCategories() 추가하거나
     → ProductService에 위임
3-2. Controller→Repository 금지 규칙 추가
3-3. 전체 테스트 통과 확인
3-4. 커밋 2개:
     - "refactor: AdminProductController에서 CategoryRepository 직접 의존 제거"
     - "test: ArchUnit — Controller의 Repository 직접 사용 금지 규칙 추가"
```

## 도입하지 않는 것 (의도적 제외)

| 도구/규칙 | 제외 이유 |
|----------|----------|
| Service 간 cross-package Repository 금지 | OrderService가 WishRepository를 써야 하는 등 현재 구조에서는 불가피. 도메인 이벤트 도입 시 재검토 |
| Checkstyle | Spotless(google-java-format)로 포매팅 충분. Checkstyle은 규칙이 과도해질 수 있음 |
| ktlint 제거 | Java 소스에 영향 없으므로 제거해도 되나, 별도 작업으로 분리 |
| 패키지 간 의존 방향 강제 | 현재 도메인 패키지 구조가 flat하여 의미 있는 계층을 정의하기 어려움. 모듈 분리 시 재검토 |

## 예상 결과물

```
build.gradle.kts          ← Spotless + ArchUnit 의존성 추가
src/test/java/gift/
  └── ArchitectureTest.java  ← 계층 규칙 테스트 (3개 규칙)
```

`./gradlew test`만 실행하면 포매팅 검증 + 계층 규칙 검증이 자동으로 수행된다.
