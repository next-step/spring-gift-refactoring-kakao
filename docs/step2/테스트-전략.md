# 2단계 테스트 전략

## 원칙

- **테스트 먼저**: 리팩토링 구현 전에 테스트를 작성하거나 수정한다.
- **실패 → 구현 → 통과**: 작동 변경은 실패하는 테스트를 먼저 작성하고, 구현 후 통과시킨다.
- **구조 변경은 기존 테스트가 안전망**: 구조만 바꾸는 경우 새 테스트 없이 기존 79개 테스트가 그대로 통과해야 한다.
- **커밋 분리**: 테스트 추가/수정 커밋과 구현 커밋을 나눈다.

현재:  재고가 99로 줄어있음 (버그 증명) → @Transactional 적용 후 통과

```
[success_removesWishAfterOrder]

When:  해당 상품의 옵션으로 주문

[success_orderWithoutWish]
Given: 위시리스트가 비어있는 회원
When:  주문
Then:  주문 성공 (201) — 위시 관련 에러 없이 정상 동작
```
