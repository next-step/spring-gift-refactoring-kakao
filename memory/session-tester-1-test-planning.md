### 2. 테스트 구축 규칙 확정

사용자와 논의하여 다음 규칙을 확정:

- `src/main/**` 수정 금지 (읽기만 가능)
- 인수 테스트(API 테스트) 중심
- R1: 외부 계약 검증 (HTTP Method + URL + Status Code + Response Body)
- R2: 테스트 하나 = 시나리오 하나
- R3: 테스트 간 독립성 (Flyway 시드 데이터 의존 금지)
- R4: 메서드명 영문 + @DisplayName 한글
- R5: 외부 의존성 격리 (Kakao API 모킹)

### 3. 작업 계획 수립

- 1단계: 순수 단위 테스트 (Entity, Validator)
- 2단계: API 인수 테스트 (Category → Member → Product → Option → Wish → Order)
- 3단계: Admin MVC 테스트 (필요 시)
