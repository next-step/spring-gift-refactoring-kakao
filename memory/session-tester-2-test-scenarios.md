# Session tester-2: 인수 테스트 시나리오

**날짜**: 2026-02-27

## 목적

리팩터링 안전망으로서, **현재 실제 코드 동작**을 기준으로 한 인수 테스트 시나리오.
API 명세와 불일치하는 부분은 코드 동작을 우선하며, 불일치 내용을 별도 기록한다.

---

## 1. 회원 API (`/api/members`)

### Happy Flow

| #   | 시나리오                     | 요청                                   | 기대 응답            |
|-----|--------------------------|--------------------------------------|------------------|
| M-1 | 회원가입 성공                  | `POST /register` `{email, password}` | `201`, `{token}` |
| M-2 | 로그인 성공                   | `POST /login` (가입한 계정)               | `200`, `{token}` |
| M-3 | 발급된 토큰으로 인증 필요 API 접근 가능 | 위 토큰으로 `GET /api/wishes`             | `200`            |

### Error Flow

| #    | 시나리오                      | 기대                                      |
|------|---------------------------|-----------------------------------------|
| M-E1 | 이메일 중복 가입                 | `400`, `"Email is already registered."` |
| M-E2 | 존재하지 않는 이메일 로그인           | `400`, `"Invalid email or password."`   |
| M-E3 | 비밀번호 불일치 로그인              | `400`, `"Invalid email or password."`   |
| M-E4 | 이메일 형식 위반 (`"not-email"`) | `400` (Spring Validation)               |
| M-E5 | 이메일 빈 값                   | `400` (Spring Validation)               |
| M-E6 | 비밀번호 빈 값                  | `400` (Spring Validation)               |

## 2. 카테고리 API (`/api/categories`)

### Happy Flow

| #   | 시나리오               | 기대                                 |
|-----|--------------------|------------------------------------|
| C-1 | 카테고리 생성            | `201`, Location 헤더, 응답 body에 id 포함 |
| C-2 | 카테고리 목록 조회         | `200`, `List<CategoryResponse>`    |
| C-3 | 카테고리 수정            | `200`, 수정된 필드 반영                   |
| C-4 | 카테고리 삭제            | `204`                              |
| C-5 | 빈 목록 조회 (데이터 없을 때) | `200`, `[]`                        |

### Error Flow

| #    | 시나리오                      | 기대    |
|------|---------------------------|-------|
| C-E1 | name 빈 값으로 생성             | `400` |
| C-E2 | color 빈 값으로 생성            | `400` |
| C-E3 | imageUrl 빈 값으로 생성         | `400` |
| C-E4 | 존재하지 않는 카테고리 수정           | `404` |
| C-E5 | description은 null 허용 (정상) | `201` |

> **코드 관찰**: `DELETE`는 존재하지 않는 ID여도 `204` 반환 (Spring Data JPA 3.x `deleteById` 동작)

## 3. 상품 API (`/api/products`)

### Happy Flow

| #   | 시나리오              | 기대                                                            |
|-----|-------------------|---------------------------------------------------------------|
| P-1 | 상품 생성             | `201`, Location 헤더, `{id, name, price, imageUrl, categoryId}` |
| P-2 | 상품 단건 조회          | `200`, `ProductResponse`                                      |
| P-3 | 상품 목록 조회 (페이지네이션) | `200`, `Page` 구조 (`content`, `totalElements` 등)               |
| P-4 | 상품 수정             | `200`, 수정 반영                                                  |
| P-5 | 상품 삭제             | `204`                                                         |

### Error Flow

| #    | 시나리오                     | 기대                                    |
|------|--------------------------|---------------------------------------|
| P-E1 | 존재하지 않는 상품 조회            | `404`                                 |
| P-E2 | 존재하지 않는 카테고리로 생성         | `404`                                 |
| P-E3 | 존재하지 않는 카테고리로 수정         | `404`                                 |
| P-E4 | 존재하지 않는 상품 수정            | `404`                                 |
| P-E5 | 이름 16자 이상                | `400`, 에러 메시지 포함                      |
| P-E6 | 이름에 허용되지 않은 특수문자 (`!@#`) | `400`                                 |
| P-E7 | 이름에 "카카오" 포함             | `400`, `"카카오"` 관련 메시지                 |
| P-E8 | 이름 빈 값                   | `400`                                 |
| P-E9 | price 0 이하               | `400` (Spring Validation `@Positive`) |

## 4. 옵션 API (`/api/products/{productId}/options`)

### Happy Flow

| #   | 시나리오             | 기대                                         |
|-----|------------------|--------------------------------------------|
| O-1 | 옵션 추가            | `201`, Location 헤더, `{id, name, quantity}` |
| O-2 | 옵션 목록 조회         | `200`, `List<OptionResponse>`              |
| O-3 | 옵션 삭제 (2개 이상일 때) | `204`                                      |

### Error Flow

| #    | 시나리오              | 기대                                     |
|------|-------------------|----------------------------------------|
| O-E1 | 존재하지 않는 상품에 옵션 조회 | `404`                                  |
| O-E2 | 존재하지 않는 상품에 옵션 추가 | `404`                                  |
| O-E3 | 중복 옵션명 추가         | `400`, `"이미 존재하는 옵션명입니다."`             |
| O-E4 | 마지막 옵션 삭제 시도      | `400`, `"옵션이 1개인 상품은 옵션을 삭제할 수 없습니다."` |
| O-E5 | 존재하지 않는 옵션 삭제     | `404`                                  |
| O-E6 | 이름 51자 이상         | `400`                                  |
| O-E7 | 이름에 허용되지 않은 특수문자  | `400`                                  |
| O-E8 | 다른 상품의 옵션 삭제 시도   | `404` (productId 불일치 검증)               |

> **코드 관찰**: `PUT` 엔드포인트가 코드에 존재하지 않음. API 명세에는 있으나 미구현 상태.

## 5. 위시 API (`/api/wishes`)

### Happy Flow

| #   | 시나리오              | 기대                                              |
|-----|-------------------|-------------------------------------------------|
| W-1 | 위시 추가             | `201`, `{id, productId, name, price, imageUrl}` |
| W-2 | 위시 목록 조회 (페이지네이션) | `200`, `Page<WishResponse>`                     |
| W-3 | 위시 삭제             | `204`                                           |
| W-4 | 동일 상품 중복 추가 (멱등성) | `200`, 기존 위시 반환                                 |

### Error Flow

| #    | 시나리오            | 기대    |
|------|-----------------|-------|
| W-E1 | 인증 없이 목록 조회     | `401` |
| W-E2 | 인증 없이 추가        | `401` |
| W-E3 | 인증 없이 삭제        | `401` |
| W-E4 | 유효하지 않은 토큰      | `401` |
| W-E5 | 존재하지 않는 상품 추가   | `404` |
| W-E6 | 다른 회원의 위시 삭제 시도 | `403` |
| W-E7 | 존재하지 않는 위시 삭제   | `404` |

## 6. 주문 API (`/api/orders`)

### Happy Flow

| #    | 시나리오                  | 기대                                                                     |
|------|-----------------------|------------------------------------------------------------------------|
| OR-1 | 주문 생성 (포인트 충분, 재고 충분) | `201`, Location 헤더, `{id, optionId, quantity, orderDateTime, message}` |
| OR-2 | 주문 후 옵션 재고 감소 확인      | 옵션 조회 시 `quantity`가 차감됨                                                |
| OR-3 | 주문 목록 조회 (페이지네이션)     | `200`, `Page<OrderResponse>`                                           |
| OR-4 | message가 null인 주문     | `201`, 정상 생성                                                           |

### Error Flow

| #     | 시나리오            | 기대                                  |
|-------|-----------------|-------------------------------------|
| OR-E1 | 인증 없이 주문 생성     | `401`                               |
| OR-E2 | 인증 없이 주문 조회     | `401`                               |
| OR-E3 | 존재하지 않는 옵션으로 주문 | `404`                               |
| OR-E4 | 재고 부족           | `500` (**@ExceptionHandler 없음**)    |
| OR-E5 | 포인트 부족          | `500` (**@ExceptionHandler 없음**)    |
| OR-E6 | quantity 0 이하   | `400` (Spring Validation `@Min(1)`) |

## 코드 vs 명세 불일치 요약

| 항목             | 명세     | 실제 코드                              |
|----------------|--------|------------------------------------|
| 옵션 수정 (`PUT`)  | 존재     | **미구현**                            |
| 주문 시 재고/포인트 부족 | `400`  | **`500`** (`@ExceptionHandler` 없음) |
| 주문 시 위시 자동 제거  | 있음     | **미구현**                            |
| 주문 트랜잭션        | 암묵적 기대 | **`@Transactional` 없음**            |

이상 4건은 Phase 2(작동 변경) 범위. 인수 테스트는 현재 코드 동작 기준으로 작성한다.
